# Session 2026-05-03

Sammanfattning av större UI-omstrukturering av kartöverlägg och ruttplanerare.

## Overlay-layout

- Flyttade ruttplaneraren till vänsterstacken direkt under infoboxen.
- Flyttade kartlagerkontrollerna till övre högra hörnet.
- Flyttade location/zoom-kontrollerna till nedre högra hörnet och gjorde zoomgruppen vertikal.
- Gjorde MapLibre-attribution permanent synlig nere till vänster i stället för stängbar info-sheet.
- Döljer live-/tidsboxarna när ruttplaneraren är aktiv, så routeflödet får mer vertikal yta.

## Routeplanner UI

- Bytte inputikoner från search till `myposition.svg` och `mydestination.svg`.
- Lade dotted linje mellan Från/Till-ikonerna.
- Höjde inputtexten till large och matchade laddspinnern mot ikonstorleken.
- Ersatte filterlistans info/toggle-rader med kompakta pills:
  - `Olycksrisk`
  - `Störningar`
  - `Höga hastigheter`
- Pills kan väljas innan Från/Till fylls i och ligger kvar när input ändras.
- Filterladdning visas som liten spinner i aktiva pills, inte som separat stor statusbox.
- Tog bort tidsbudget-slidern ur UI:t. När undvik-filter är aktiva används ett öppet kandidatläge så användaren får se relevanta alternativ i stället för att styra med slider.

## Route-alternativ

- Default utan aktiva undvik-filter visar bara snabbaste rutten.
- När filter är aktiva visas flera ruttalternativ som kort under ruttpanelen.
- Alternativkort visar titel, kort motivering, tid och distans.
- Korttitlar/motiveringar bygger på befintliga `avoidScores` och `exposure`, inklusive ett första heuristiskt `Liten utmaning`-läge för rutter med viss men reducerad 90+-exponering.
- Alternativlistan sorteras på tid och byter inte ordning när användaren väljer ett alternativ.
- Vald rutt är separat state från listordningen och skickas till kartlagret via `selectedRouteId`.
- Hover/focus på ett alternativ tänder motsvarande ruttlinje i kartan utan att flytta korten.
- Alternativlistan scrollar internt utan scrollbar. Bottenfade visas bara när listan faktiskt har overflow.

## Kartlager

- `setRouteLayerData` tar nu ett valfritt `selectedRouteId`, så kartans markerade rutt inte behöver vara första objektet i listan.
- Primär/alternativ route-styling återanvänds, men UI:t kan nu hålla stabil tidssorterad lista samtidigt som kartan markerar valt eller hoverat alternativ.

## GraphHopper lokalt

- Startade dev-servern med inline GraphHopper-env via token från routingservern, utan att skriva token i `.env`.
- Verifierade `/api/route` preview med `provider: "graphhopper"`.
